## 記事を増やす方針
- 毎週のレポート末尾の「次に書く記事候補」（表示はあるが順位8〜20位の検索語）を基準に、定番型の記事を書く。
- 同じ話題で表示が伸びている記事は、新記事を量産するより既存記事を更新する（施策4・6）。

## 施策を追加するとき
1. サイトに反映して push した日を `started` にして `experiments.json` に1件足す（`pages` は記事番号、比較用に触らない記事を `control_pages` に入れる）。
2. この表の状態を「実施中」にする。
3. 週次レポートの判定が2週続けて同じ向きになったら、表の状態を「うまくいった可能性 / ダメだった可能性」に更新する。

## Instagram（@sixten）のエンゲージ

2026-10-06 設置（クリス指示「常にエンゲージは見て欲しいし、その上でプロのマーケターとして目線でいろいろ試して、データを集めて、ニュースがより広まり、インスタのフォロワーが伸びるようにして欲しい」）。サイト側の施策とはファイルを分けている（`experiments.json` は weekly_report.py が全件の `pages` を読むので IG の実験を混ぜない）。

### 計測の場所
- 毎日 JST 8:30 に `.github/workflows/ig-insights.yml` が `growth/ig/fetch_ig.py` → `growth/ig/report.py` を走らせて commit する。トークンはリール自動投稿と同じ Secret `IG_TOKEN`。失敗しても取れたぶんだけ保存して正常終了する。手で回すときは Actions の「IG insights daily」→ Run workflow、またはローカルで `python3 journal_auto/growth/ig/fetch_ig.py && python3 journal_auto/growth/ig/report.py`（トークンは `~/.claude/state/ig_token.txt`）。
- `growth/ig/data/`
  - `account_snapshots.jsonl` … フォロワー数・投稿数（取得のたびに1行）。純増はこの差分。
  - `account_daily.json` … 日別（太平洋時間区切り）のリーチ・再生・プロフィール訪問・反応・シェア・保存・フォロー/解除。
  - `media/YYYY-MM-DD.json` … 全リールの累計指標のスナップショット（投稿60日以内は毎日・それより古いものは月曜だけ）。経過日数ごとの伸びはここから出す。
  - `media_index.json` … メディアID → 記事番号・テンプレ・背景経路・カテゴリ・出典・選手・キャプション長・実験アーム。
  - `demographics/YYYY-MM.json` … フォロワーの年齢・性別・地域。
- 取れない指標: リール単位のフォロー数・プロフィール訪問（API がリールに対応していない）。フォローはアカウント日別で見る。事業アカウント化より前の投稿3本は指標自体が取れない。

### レポートの見方（`growth/ig/REPORT.md`）
- 比べる数字は「投稿72時間時点」の views/reach（累計のままだと古い投稿ほど有利になるため）。計測開始前の投稿は72時間以上たった現在値で代用している。
- 率は「合計 ÷ リーチ合計」。シェア率・保存率がアルゴリズム上いちばん効く（IG はリールの「送られた数」を重く見る）ので、views と並べて必ず見る。
- 10本未満のグループは「参考値」。カテゴリと背景（KICKS はほぼ選手写真なし等）が重なっているので、1つの表だけで原因を決めない。

### 実験の回し方・止め方
- 定義は `growth/ig/experiments.json`。`status: running` で期間内のものだけ、`journal_auto/ig_experiments.py` が投稿直前のキャプションに効かせる（reel_post.py から呼ぶ）。どのアームで出したかは video_status.json の `exp_arms` に残り、`media_index.json` の `arms` に写る。キャプション本文の文言（`cta_share` / `cta_follow_b`）でも判定できる。
- 変えてよいのは CTA の1行だけ。見出し・要点・出典・写真クレジット・ハッシュタグ・動画（背景写真の規則・BGM）には実験で触らない。
- **止める**: `status` を `stopped` にして push → 次の投稿から元のキャプションに戻る。`ig_experiments.py` は読めない・壊れている時も元のキャプションを返す（投稿は止まらない）。
- **採用する**: REPORT.md の判定が「採用候補」になったら、クリスに見せてから `ig_queue.build_caption` 本体の文面を変え、実験は `status: adopted` にする（勝手に本体へ入れない）。
- **新しい実験を足す**: 1回に動かす変数は投稿単位で1つ・週単位で1つまで（同時に同じ行を変える実験を重ねない）。仮説・変数・期間・判定指標・判定基準を先に書いてから回す。
